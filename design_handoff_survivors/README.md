# Handoff: Управление выжившими (Roblox UI, тема «Океан»)

## Overview
Меню управления командой выживших (капитанов). Здесь игрок:
- видит список выживших с уровнем, местом работы, главным бонусом, зарплатой и настроением;
- открывает страницу выжившего: слева 3D-предпросмотр, здоровье, настроение и **бонусы капитана**, справа **назначение в конкретное здание** (с превью здания и числом рабочих мест), **зарплата**, показатели, кнопки «Сохранить» и «Выгнать».

Стиль и структура совпадают с магазином торговца и окном крафта (тема «Океан»): панель слева, основной блок справа.

## About the Design Files
`Управление выжившими.dc.html` — **дизайн-референс в HTML**. Это прототип, который показывает внешний вид и поведение, а не продакшн-код. Его нужно **пересобрать в Roblox Studio** (ScreenGui + ViewportFrame + Luau, клиент и сервер) по паттернам проекта. Если в проекте есть UI-фреймворк (Roact/React-lua, Fusion), используйте его. Если нет, стройте на обычных Instance.
Файл открывается в браузере (рядом нужен `support.js`). Стили инлайновые, значения можно брать прямо из разметки. Вся логика прототипа — в классе `Component` внизу файла.

## Fidelity
**High-fidelity.** Цвета, радиусы, обводки, размеры, тексты и состояния финальные.
Заглушки:
- портрет / 3D-модель персонажа (в прототипе одна картинка с разными оттенками; в игре — ViewportFrame с моделью конкретного NPC);
- превью зданий (полосатые блоки; в игре — рендеры зданий в ImageLabel или ViewportFrame с моделью);
- иконки бонусов (символы $, ⚡, ♥, ★, ⚒ — заменить на иконки игры).

Размеры даны в px для 1920×1080. В Roblox используйте `UIScale` или Scale-размеры.

## Interactions & Behavior
- Клик по строке → страница B. «‹» или ✕ → назад к списку
- Фильтры: «Работают» — job ≠ отдых, «Отдыхают» — job = отдых, «Недовольны» — mood < 35
- **Назначение в здание:** клик по свободной карточке переводит капитана туда. Место в старом здании освобождается, счётчики «N / M» обновляются у обоих зданий. Занятые карточки клики игнорируют
- **Зарплата:** шаг 5, диапазон 0–100. Изменения применяются по «Сохранить» (в прототипе — сразу; в игре лучше держать черновик и коммитить на сервер по «Сохранить»)
- **Выгнать:** нужен диалог подтверждения (в прототипе его нет). После подтверждения капитан удаляется, место в здании освобождается, возврат к списку
- **Формулы прототипа** (балансные заглушки, заменить на реальные):
  - `mood = clamp(10, 100, round(salary * 1.1 + 15 + (rest ? 20 : 0)))`
  - `speed = round(60 + mood * 0.6)` %; если капитан отдыхает — `—`
  - `xp = level * 120`
- Анимации: смена списка и страницы — fade + сдвиг X ±24 px за 0.2 c (Quad/Out). Выбор карточки здания — scale 0.96 → 1 за 0.12 c. Полосы анимировать по Size за 0.25 c

## State Management
**Сервер (источник истины)**
- `survivors[userId]: { id, name, level, xp, hp, salary, buildingId | nil, modelId, bonuses: [{ kind, value, type }] }`
- `buildings[userId]: { id, name, place, capacity, previewImage, workers: {survivorId} }` — это реальные здания, построенные на плоту игрока; capacity может расти с улучшением здания
- Remotes:
  - `Survivors:Assign(survivorId, buildingId | nil)` — проверить, что есть свободное место
  - `Survivors:SetSalary(survivorId, value)` — проверить диапазон
  - `Survivors:Fire(survivorId)`
- Бонусы применяются на сервере: «Пассивный» действует всегда, «На работе» — только пока капитан назначен в здание (при необходимости — в здание определённого типа), «Аура» — на соседей по зданию

**Клиент**
- `view: 'list' | 'detail'`, `selectedId`, `filter`, черновик зарплаты (до «Сохранить»)
- Данные выживших и зданий реплицируются (ReplicaService / Attributes / RemoteEvent `Survivors.Changed`)

# Пират

Папка содержит актуальный серверный скрипт для NPC Пирата в Roblox Studio.

## Файлы

- `PirateAI.server.lua` — единый скрипт для физики, коллайдеров, анимаций, преследования игрока и атаки.

## Как вставить в Roblox Studio

1. В модели Пирата оставь структуру:

   ```text
   Pirate
   ├─ Script
   ├─ BodyColliders
   │  ├─ HeadCollider
   │  ├─ LeftLegCollider
   │  ├─ LeftHandCollider
   │  ├─ RightHandCollider
   │  ├─ RightLegCollider
   │  └─ TorsoCollider
   ├─ Pirate
   ├─ AnimationController
   │  └─ Animator
   ├─ Idle
   ├─ Walk
   ├─ Run
   ├─ Attack
   └─ PatrolPoints   (необязательно: Part'ы-маркеры маршрута патруля)
   ```

2. Скопируй содержимое `PirateAI.server.lua` в обычный серверный `Script` внутри модели Пирата.
3. У объектов `Idle`, `Walk`, `Run`, `Attack` должны быть выставлены правильные `AnimationId` именно для Пирата.
4. Отключи старые скрипты, которые отдельно приваривали коллайдеры, запускали анимации или двигали Пирата, чтобы не было конфликтов.

## Логика поведения

### Здоровье (HP) без Humanoid

В модель **не нужно** добавлять `Humanoid`. Он ломает этот тип юнита:

- перехватывает анимации у `AnimationController` (у модели должен быть либо
  `Humanoid`, либо `AnimationController`, но не оба сразу) — анимации перестают играть;
- запускает свою физическую state-machine поверх ручного движения
  (`AssemblyLinearVelocity`, `AlignOrientation`, велды) — ломается физика.

Поэтому HP сделано без Humanoid. Если `Humanoid` остался от старых
экспериментов, скрипт сам удалит его при запуске.

- Стартовое HP задаётся константой `UNIT_MAX_HEALTH = 100` в начале скрипта.
- Здоровье хранится в **атрибутах модели**: `Health` и `MaxHealth` (видны во
  вкладке Attributes и реплицируются на клиент — удобно для полоски HP).
- Урон/лечение из других скриптов — через `BindableFunction` внутри модели:
  - `model.TakeDamage:Invoke(20)` — нанести 20 урона (возвращает остаток HP);
  - `model.Heal:Invoke(10)` — вылечить на 10.
- Можно менять `Health` и напрямую через атрибут — значение само ограничится
  диапазоном `0..MaxHealth`.
- При смерти срабатывает `BindableEvent` `model.Died` (аналог `Humanoid.Died`) —
  на него можно повесить дроп лута или зачёт квеста. Если
  `DESTROY_ON_DEATH = true`, модель удалится через 3 секунды.

### Хитбокс получения урона

Классический меч игрока бьёт через `Handle.Touched` →
`FindFirstChildOfClass("Humanoid")`, а у юнита Humanoid нет — поэтому обычное
оружие по нему не попадает. Юнит принимает урон сам, по своим коллайдерам:

- скрипт слушает взмах оружия игрока (`Tool.Activated`) и проверяет, дотянулось
  ли оружие (`Handle`) или сам игрок до любого коллайдера из `BodyColliders`;
- если да — вызывается `TakeDamage`. Работает с любым инструментом, **без правок
  в самом оружии** и без Humanoid.
- На `collider.Touched` полагаться нельзя: коллайдеры ног/головы/рук лежат в
  коллизионных группах, несовместимых с группой игрока, а это глушит `Touched`.
  Поэтому попадание ловится запросом по расстоянию.
- Настройки в секции «ХИТБОКС ПОЛУЧЕНИЯ УРОНА»:
  - `DEFAULT_WEAPON_DAMAGE = 10` — урон за удар, если у оружия не задан свой;
  - `HIT_REACH = 4.5` — на каком расстоянии до коллайдера засчитывается удар;
  - `HIT_DEBOUNCE = 0.4` — не чаще одного удара от игрока за это время.
- Урон конкретного оружия можно задать атрибутом `Damage` (или `NumberValue`
  `Damage`) прямо на Tool — он перекроет `DEFAULT_WEAPON_DAMAGE`.

### Полоска здоровья (HP bar)

Над головой юнита скрипт сам создаёт `BillboardGui` с полоской HP, которая
читает атрибут `Health` (зелёная → красная по мере урона). Видно всем игрокам,
удобно проверять, проходит ли урон. Отключить: `SHOW_HEALTH_BAR = false` в
секции «ПОЛОСКА ЗДОРОВЬЯ».

### Устойчивость на поверхности

Раньше при контакте с неровной поверхностью NPC иногда подбрасывало в небо
(физика выталкивала коллайдеры через позицию, и ограничение скорости это не
ловило). Теперь `stabilizeOnGround` каждый кадр сверяет нижнюю точку ног с
землёй (raycast):

- просел под пол → плавно поднимает;
- подбросило выше нормы (> `MAX_HOVER_ABOVE_GROUND = 2.5` studs над землёй) →
  жёстко возвращает к земле и гасит вертикальную/угловую скорость;
- в норме → просто не даёт резко взлетать (`MAX_UPWARD_VELOCITY`).

Юниты больше **не встают друг на друга «лесенкой»**: каждый помечен тегом
`RaftMeleeUnit`, и raycast «земли» игнорирует хитбоксы других юнитов (раньше
сосед принимался за пол, и юнит залезал на него как на ступеньку). Толкать
юнита по-прежнему можно — коллайдер тела сталкивается с игроком; но друг с
другом юниты не сталкиваются и при движении мягко расходятся
(`SEPARATION_RADIUS`, `SEPARATION_STRENGTH`).

### Поведение: Страж (FSM) — Этапы 1-3

Пират работает как конечный автомат (FSM) со состояниями:

- **Guard** — стоит на точке спавна (`Idle`, «оглядывается») ~`GUARD_DURATION` сек.
- **Patrol** — обходит маркеры из папки `PatrolPoints` по порядку имён, стоит на
  каждой точке случайные `PATROL_PAUSE_MIN..MAX` (10-30) сек, потом возвращается
  на пост. Нет папки/пуста → просто охраняет точку спавна.
- **Investigate** — подозрение ≥ `SUSPICION_INVESTIGATE` (50%): идёт к месту,
  где заметил игрока, и осматривается.
- **Chase / Attack** — подозрение 100% и видит врага: бежит (`Run`) и бьёт
  (`Attack`) в радиусе `ATTACK_RANGE`.
- **Search** — потерял из виду: ищет у последней известной точки `SEARCH_DURATION` сек.
- **Return** — не нашёл: возвращается на пост и снова охраняет (память места).
- **Alerted** — поднят по тревоге отряда: подтягивается к месту крика,
  осматриваясь; войдя в зону боя — переходит к активной проверке.

**Зрение (стиль Far Cry / AC):** считает угол от «глаз» (`HeadCollider`) до
игрока. Спереди (`FOV_FRONT_DEGREES`) замечает быстро, сбоку
(`FOV_SIDE_DEGREES`) — медленно, сзади — не видит. Обзор рвётся стеной (луч
`Raycast`). Над головой белая полоса подозрения: белая → жёлтая (≥50%) →
красная (100%).

Маркеры в `PatrolPoints` удобно сделать `Anchored`, `CanCollide = false`,
`Transparency = 1`. Имена задают порядок обхода (например `01`, `02`, `03`).

**Тревога отряда (Этап 2):** на 100% пират «кричит» — пираты с тегом
`PirateGuard` в радиусе `SQUAD_ALERT_RADIUS` (200) поднимаются. Кто ближе
`SQUAD_ENGAGE_RADIUS` (60) к месту тревоги — идут проверять/в бой; дальние
переходят в боевую готовность и подтягиваются, вступая волнами (не всей
пачкой). Крик передаётся атрибутами `AlertClock`/`AlertPosition`.

**Навигация (Этап 3):** к цели (маркер, игрок, место тревоги, пост) пират идёт
через `PathfindingService` — обходит препятствия и воду (`Costs.Water = ∞`), а
не упирается в них. Путь пересчитывается, когда цель сместилась
(`PATH_GOAL_MOVE_THRESHOLD`) или по таймеру (`PATH_RECOMPUTE_INTERVAL`); сам
расчёт идёт в отдельном потоке (`ComputeAsync`), а движение по waypoints — нашим
`moveTowards` (с разведением). Перелаз препятствий (анимация `Up`) пока выключен
(`AgentCanJump = false`). Если путь не найден (цель за водой) — пират не лезет
напрямую, а останавливается.

> Готово Этап 3. Размер агента под габариты модели — `AGENT_RADIUS` /
> `AGENT_HEIGHT`.

## 4. Серверный поток (P2) — важно

Rewarded video в Roblox: награда — **developer product**. Проверь актуальную документацию перед реализацией: <https://create.roblox.com/docs/production/promotion/rewarded-video-ads>.

- Клиент: `AdService:GetAdAvailabilityNowAsync(Enum.AdFormat.RewardedVideo)` — перед показом кнопки/карточки; нет рекламы → точку входа не показываем.
- Сервер: `AdService:CreateAdRewardFromDevProductId(DEV_PRODUCT_ID)` → `AdService:ShowRewardedVideoAdAsync(player, reward, placementId)`.
- Выдача: в `MarketplaceService.ProcessReceipt` по `receiptInfo.ProductId == DEV_PRODUCT_ID`.

**Награда динамическая, а dev product один.** Поэтому:

1. Сервер сам считает оффер: `pendingOffer[player] = { placement, resources, createdAt, expiresAt }`. Для нехватки — ровно недостающее, обрезанное потолком (`Config.RewardCap`, напр. 20 брёвен / 3 слитка). Для рейда — добыча последнего рейда. **Клиент не присылает количества** — только `placement`.
2. `RewardAds_Watch(placement)` → сервер проверяет, что оффер жив и совпадает, pacing не нарушен → показывает рекламу.
3. `ProcessReceipt` → берёт `pendingOffer[player]`, выдаёт через существующий сервис инвентаря, очищает оффер, фиксирует `PurchaseId` (идемпотентность — ресивер может прийти повторно), шлёт `RewardAds_Granted(resources)` для анимации «дождя» иконок, возвращает `PurchaseGranted`.
4. **Если `ProcessReceipt` уже есть — добавь ветку в существующий обработчик**, не переназначай.
5. Без рекламы в Studio: `Config.DebugFakeAds = true` (только `RunService:IsStudio()`) — сразу вызывает выдачу, чтобы UI можно было проверить.

Ограничения Roblox: игра должна быть допущена к рекламе (≥2 000 уникальных посетителей в месяц, аккаунт 13+, верификация, 2FA); награду выдавать сразу после просмотра; рекламу нельзя делать обязательным «шлагбаумом» прогресса.

### Табличка Лодочника: бесплатно + Robux

Оффер рейда на сервере: `raidOffer[player] = { free = {1–2 Resource}, premium = {1–2 Resource}, priceAll, pricePremium, freeClaimedAt? }`. Состав и цены решает сервер (`Config.RaidReward`).

- **«Бесплатно»** → `RewardAds_Watch("boatman")`. Если `Config.FreeRequiresAd = true` (по умолчанию) — поток рекламы выше, выдаёт **только `free`**. Если `false` — сервер выдаёт `free` сразу, с тем же cooldown. После выдачи — `freeClaimedAt`, клиенту состояние `claimed`.
- **«R$ N»** → `RewardAds_Buy("boatman")` → сервер вызывает `MarketplaceService:PromptProductPurchase(player, id)`:
  - до бесплатного — dev product **`RaidAll`** (`priceAll`): выдаёт `free + premium`, бесплатное на этот рейд сгорает;
  - после бесплатного — dev product **`RaidPremium`** (`pricePremium`): выдаёт только `premium`.
  - Цена в Roblox задаётся в самом dev product; UI берёт её из `MarketplaceService:GetProductInfo(id, Enum.InfoType.Product).PriceInRobux` (кэшировать), не хардкодить.
- `ProcessReceipt`: по `ProductId` → берёт `raidOffer[player]`, выдаёт нужную часть, закрывает оффер, идемпотентно по `PurchaseId`. Если оффера нет (игрок перезашёл) — всё равно выдать то, за что заплачено (хранить последний оффер в данных игрока до выдачи) и вернуть `PurchaseGranted` только после сохранения.
- Отказ от покупки (`PromptProductPurchaseFinished`, `isPurchased = false`) — табличка остаётся как была.
- Значок Robux на кнопке — официальный глиф из шрифта Roblox (`utf8.char(0xE002)` в `TextLabel`) или стандартная иконка Robux; в макетах — плашка «R$».

### Правила показа (диздок, раздел 4.1) — всё в `Config`

- Между предложениями ≥ **180 с**, ≤ **6 в час**, ≈ **20 в день** на игрока (считает сервер).
- **Никогда**: ночная волна, бой (урон за последние 10 с), катсцена, экран смерти, первые 5 мин новичка.
- Триггер карточки — **конкретная нехватка**: навёл молоток на постройку и не хватает 1–30%; открыл рецепт без материалов; кончилось топливо; не хватает на улучшение.
- Нет нехватки 3+ мин → вариант «Бонус течения» (сундук за рекламу), не чаще раза в 10 мин.
- Табличка у Лодочника (P1) — своё правило: доступна после рейда, после просмотра — cooldown (`Config.RaidRepeatCooldown`, по умолчанию 4–5 мин; уточни у владельца).

## 5. Спецификации компонентов

Все значения — из `Theme.luau`. Текст белый (`ink`) с `UIStroke` 2px `outline` (`ApplyStrokeMode.Contextual`), шрифт Builder Sans Heavy/Bold. Иконки — `ImageLabel` из `ResourceIcons`.

### 5.1 ResourceChip (`05-ResourceChip.png`)
- Frame 52×52 (`sm` 36, узкий режим 42), фон `panel-raised`, `UICorner` 8, `UIStroke` 2 `outline`.
- Иконка 72% размера, центр, чуть выше центра (−6%).
- Количество `+N` — правый нижний угол, выступает на 3px вниз, `TextSize` 15 (sm 12), цвет `reward`, Heavy, обводка. `≥1000` → `1.2K`.
- «Ещё» — прозрачный фон, пунктирная рамка `ink-muted` (в Roblox — `UIStroke` + `Transparency 0.3` или 9-slice), текст `+N` белый.

### 5.2 ChipRow (общая логика)
- `UIListLayout` Horizontal, Padding 8, `AutomaticSize = X`, выравнивание — по центру (billboard) / слева (card).
- `maxVisible = 4`: если ресурсов больше — первые 3 + ячейка «+N» (N = остаток).
- Пересборка при изменении оффера: переиспользуй чипы (пул), не пересоздавай каждый кадр.

## 6. Адаптивность

- Все ScreenGui-элементы — через один `UIScale`: `scale = math.clamp(viewport.Y / 900, 0.7, 1.25)`, пересчёт на `ViewportSize` changed.
- Размеры внутри — Offset (из Theme), не Scale: так макеты совпадают пиксель в пиксель, а масштаб управляется одним UIScale.
- Проверить: 1920×1080, 1366×768, телефон (портрет/ландшафт в эмуляторе Studio), планшет. Карточка не должна перекрывать хотбар и полосы здоровья/воды/еды.
- `GuiService:GetGuiInset()` / `SafeAreaCompatibility` — не залезать под вырезы телефонов.

## 7. Иконки

1. Загрузи `design/icons/*.png` как Decals/Images (Asset Manager → Bulk Import) и впиши id в `ResourceIcons.luau`.
2. Пока id нет — используй плейсхолдер (буква ресурса в цветном квадрате) и выведи предупреждение в Output, чтобы не забыть.

## 8. Критерии готовности

# Пассивная добыча дерева (Tree Farm) — План механики

Статус: **черновик плана**, ждёт подтверждения ключевых решений (см. §8).

## 1. Суть

На острове стоит борд **«ДОБЫЧА ДЕРЕВА»** (модель `Tree_Farm`). Игрок тратит
валюту **«жители/наёмники»** (старт 20, показывается справа вверху) и «строит»
ферму. Появляется рабочий-`Villager_Axe` (R6 Humanoid с топором), который по кругу:

1. идёт к дереву и **рубит** его (база 60 c) → получает 1 бревно (`Log`);
2. несёт бревно на **склад** (`Storage_Palm`, парт `Triger`), играет анимацию
   `Drop` и **кладёт** бревно в склад;
3. идёт на **свободное место отдыха** (`Sit`, их 3, выбирает случайно из свободных),
   садится (`Sitting`) и **отдыхает** (база 30 c);
4. возвращается к дереву — цикл повторяется.

Склад накапливает брёвна. Игрок **открывает склад как сундук** и забирает брёвна в
инвентарь.

## 2. Апгрейды борда (GUI `Work`)

| Категория | Что делает | Уровни | Цена (с картинки) |
|---|---|---|---|
| **Speed** (Повысить скорость) | уменьшает время рубки 60 c → 55 c → … | 1/20 | 5 брёвен |
| **Workers** (Рабочие) | +1 рабочий (макс. 3) | 1/3 | 5 «пиратов» (?) |
| **Rest_time** (Время отдыха) | уменьшает отдых 30 c → 25 c → … | 1/10 | 5 кокосов |

Каждый блок: кнопки `Buy`/`Max`, тексты `Level`/`Price`/`Current_Status`/`Description`.
(От апгрейдов также зависит скорость ходьбы рабочего.)

## 3. Состояния рабочего (FSM)

```
SPAWN(у Spawnpoint_Work, анимации из папки Animation)
  → GO_TREE   (Walk/Run к точке рубки)
  → CHOP      (Axe_1/Axe_2, длительность = chopTime(SpeedLevel)); по концу +1 Log
  → GO_STORE  (Walk/Run к Storage_Palm/Triger)
  → DROP      (анимация Drop; кладём 1 Log в слот склада)
  → GO_REST   (Walk/Run к случайному свободному Sit; если занято — следующий)
  → REST      (Sitting, длительность = restTime(RestLevel))
  → GO_TREE …
```

- До 3 рабочих (по `WorkersLevel`), каждый — независимый FSM.
- 3 места `Sit`; занятость места помечаем (атрибут/таблица), чтобы двое не сели в одно.
- Движение: `Humanoid:MoveTo` (+ простой PathfindingService, как у пиратов), скорость
  `WalkSpeed` зависит от апгрейдов.

## 4. Где хранить состояние

- **Ферма** (построена ли, уровни апгрейдов): атрибуты на модели `Tree_Farm`
  (`Built`, `SpeedLevel`, `WorkersLevel`, `RestLevel`) — реплицируются на клиент,
  борд читает их для отрисовки. Логика — на сервере.
- **Склад**: переиспользуем систему контейнеров — слоты как атрибуты
  `SlotCount`, `Slot{i}_Name`, `Slot{i}_Count` на модели `Storage_Palm`.
- **Валюта «жители»**: IntValue в `player.Characteristics` (старт 20) — **или**
  существующая merc-инфраструктура (см. §8).

## 5. Интеграция с существующими системами (уже в проекте)

- **Инвентарь** (`InventoryManager.server.lua`):
  - `_G.AddResourceToInventory(player, "Log", n, nil, true)` — выдать брёвна.
  - `_G.RemoveResourceFromInventory(player, name, n)` — списать ресурс (для апгрейдов).
  - `_G.GetInventory(player)` / `_G.GetInventoryCapacity(player, name)`.
  - Ресурсы: бревно = `Log`, кокос = `Coconut` (есть в `RESOURCE_NAMES`).
- **Склад = сундук** (`SmallContainerSystem`/`PlasticContainerSystem` +
  `ContainerUI.client.lua`):
  - На складе ставим `ProximityPrompt` → по нажатию `OpenContainer:FireClient(player, storage)`.
  - Перенос предметов клиент↔сервер — событие `ContainerAction` (`take`/`put`/`move`),
    UI уже generic (читает `SlotCount`). **Свой UI писать почти не нужно.**
  - Рабочий «кладёт бревно» = сервер добавляет `Log` в слоты склада (не в инвентарь
    игрока). Игрок потом забирает.
- **Валюта/HUD**: статы — IntValue в `Characteristics` (как `Level`/`Mana`); HUD
  сверху-справа — новый `ScreenGui` по образцу `DayCounterUI.client.lua`,
  слушает IntValue.

## 6. Конфигурация (всё параметризуемо)

Все пути к моделям/партам и числа — в таблице `CFG` в начале скрипта, чтобы легко
подогнать под точную иерархию:
- `Tree_Farm` (борд): `Part/Unwork`, `Part/Work/Frame/{Speed,Workers,Rest_time}`.
- `Spawnpoint_Work` (точка спавна рабочего).
- Дерево для рубки + точка рубки (по скриншоту — `palm_solo/Palm`).
- `Sit` × 3 (места отдыха).
- `Storage_Palm/Triger` (точка выкладки + контейнер).
- Числа: `CHOP_BASE=60`, `CHOP_STEP`, `REST_BASE=30`, `REST_STEP`, `WORKERS_MAX=3`,
  `SPEED_MAX=20`, `REST_MAX=10`, скорости ходьбы, цены апгрейдов, старт валюты `=20`.

## 7. Файлы, которые создам

- `src/ServerScriptService/TreeFarm/TreeFarmSystem.server.lua` — сервер: борд
  (build/upgrade), спавн и FSM рабочих, выкладка в склад, ProximityPrompt склада.
- `src/StarterPlayerScripts/TreeFarmBoard.client.lua` — клики кнопок борда
  (`Начать`, `Buy`, `Max`) → RemoteEvent; отрисовка текста по атрибутам.
- Валюта «жители»: IntValue в `Characteristics` + `src/StarterPlayerScripts/VillagerCounterUI.client.lua` (HUD).
- Склад — отдельный мини-скрипт по образцу контейнеров (или внутри TreeFarmSystem).

## 8. Решения, которые нужны от тебя (до кода)

1. **Ферма общая (островная) или у каждого игрока своя?** Сейчас системы захвата
   островов нет. Предлагаю: **общая островная** — кто построил, та работает для всех;
   склад общий; апгрейды покупает любой за свои ресурсы. (Проще и логичнее для острова.)
2. **Валюта «жители»** — завести **новую** (`Villagers`/`Mercenaries` IntValue в
   `Characteristics`, старт 20) или использовать **существующую merc-валюту**
   (Gems/Iron/Currency, которую читает `MercenariesMenu`)? Это разные вещи: боевые
   наёмники vs население-рабочие. Предлагаю — **новую `Villagers`**.
3. **Цена апгрейда Workers — «5 пиратов»**: что такое «пират» как валюта? Это ресурс
   из инвентаря, отдельный счётчик, или опечатка (имелось «жителей»)? Уточни.
4. **Подтверди иерархию/имена** из §6 (или поправь): где точно `Spawnpoint_Work`,
   какое дерево рубится и где «точка рубки», где `Sit`-парты (в `palm_solo/Palm`?),
   где `Triger` склада.

После ответов сразу пишу рабочую первую версию (борд + рабочий + склад + валюта).
